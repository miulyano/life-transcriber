## [Unreleased]

### Added

- Проценты в статус-сообщении: реальный прогресс скачивания yt-dlp и прогресс транскрибации показываются цифрами `NN%` рядом с баром; при форматировании длинного текста — счётчик частей `N/M`
- Источник записи в карточке Mini App (`YouTube`, `Яндекс Диск`, `Голосовое`, `Файл`…) — ссылки теперь сохраняются с конкретной платформой вместо общего `link`; у старых записей-ссылок остаётся «Ссылка»
- Строка «Источник: … · 🕒 с таймкодами / без таймкодов» во всех сообщениях с транскриптом: первичная доставка, повторная отправка из Mini App, файл «Очищенный текст»
- Кнопка «🕒 С таймкодами» в Mini App скрыта у записей без сохранённых сегментов (раньше молча слала вариант без таймкодов); повторная отправка файлом теперь показывает шапку с каналом, как первичная доставка
- Параллельные транскрибации: несколько запросов (сообщений со ссылками/медиа) обрабатываются одновременно, независимыми задачами — новая транскрибация не ждёт окончания предыдущей
- Лимит одновременных транскрибаций `MAX_CONCURRENT_TRANSCRIPTIONS` (default 3); задачи сверх лимита ждут со статусом «В очереди…»
- Кнопка «✖️ Отменить» на статус-сообщении уже запущенной транскрибации: снимает задачу, убивает процессы yt-dlp/ffmpeg, чистит временные файлы
- Резервирование месячного лимита часов на старте задачи (оценка длительности через ffprobe): параллельные задачи одного пользователя больше не проскакивают проверку лимита все разом
- Канал/автор в карточке записи Mini App: строка `📺 <канал>` под заголовком, если у источника известен канал (сохраняется в новой колонке `channel` в SQLite, старые БД мигрируются автоматически; у старых записей канала нет)
- Кнопка «✖️ Отменить транскрибацию» в вопросе «Как прислать результат?» — удаляет запрос и снимает задачу из очереди ожидания

### Fixed

- Ошибка скачивания yt-dlp теперь пишется в лог (`logger.warning`) перед показом пользователю обобщённого «Не удалось скачать…»: транзиентные отказы платформ (SABR/403 у YouTube и т.п.) больше не слепая зона
- Ссылки из пересланных постов теперь распознаются: URL ищется не только в тексте, но и в подписи к медиа (caption) и в entities Telegram (`url`, `text_link`) — включая скрытые гиперссылки, где адреса нет в видимом тексте
- Кнопка «🕒 С таймкодами» в Mini App скрыта у коротких записей (не длиннее порога `LONG_TEXT_THRESHOLD` — они доставляются в чат без таймкодов); сервер игнорирует флаг `timecoded` при повторной отправке таких записей
- «Прислать в чат» в Mini App больше не подвешивает интерфейс: отправка ушла в фон под статус-сообщение «Отправляю результат…» в чате (та же статусная модель, что у загрузки файла), ошибки доставки показываются в чате
- Повторная отправка короткой транскрибации в чат теперь использует HTML-разметку (`body_html`): жирный заголовок, экранирование спецсимволов — раньше сырой текст с `<`, `>`, `&` мог ломать разбор Telegram
- Telegram WebView мог отдавать устаревший `app.js` из кэша после деплоя (свежая разметка + мёртвые обработчики — вкладка «Мои записи» не открывалась). Статика теперь отдаётся с `Cache-Control: no-cache`, скрипт подключается с версионным параметром

### Removed

- Кнопка «Скачать» в карточке записи Mini App — blob-download не работает во WebView Telegram; скачивание `.txt` остаётся в REST API (`/api/transcripts/{id}/file`)

### Changed

- Приветствие `/start`, `/help` актуализировано: выбор формата (с таймкодами/без) перед стартом, Mini App «Транскрибации» вместо устаревшей «кнопки 📤», новый блок про «Мои записи»
- Кнопки карточки записи в Mini App получили видимые подписи: «📨 Прислать в чат», «🕒 С таймкодами»; удаление — иконка-корзина; после отправки в чат Mini App закрывается автоматически
- Кнопка меню бота переименована: «📤 Загрузить файл» → «Транскрибации» (Mini App теперь не только про загрузку — там же список всех генераций)

### Added

- Персистентное хранение готовых транскрибаций: метаданные в SQLite (`data/transcripts.db`), текст без таймкодов в `data/transcripts/<id>.txt`, тайминги сегментов в `<id>.json` — версия с таймкодами рендерится по запросу
- REST API управления транскрибациями (`/api/transcripts`): список, скачивание `.txt`, удаление вместе с файлами, повторная отправка в чат (обычная и с таймкодами); доступ разграничен по пользователям
- Bearer-токены для API-доступа агентов (`API_TOKENS=token:user_id,...`) в дополнение к initData Mini App
- Вкладка «Мои записи» в Mini App: список генераций с кнопками скачать / в чат / в чат с таймкодами / удалить
- Выбор «С таймкодами / Без таймкодов» перед генерацией: бот спрашивает после получения ссылки или медиа, транскрибация стартует по нажатию; в webapp-форме — переключатель

### Changed

- `render_with_timecodes` разбит на `build_timecode_segments` + `render_timecode_segments`; `custom_spelling` применяется на уровне сегментов (поведение рендера не изменилось)

## [1.6.0] – 2026-07-02

### Changed

- Для файловых источников (ссылка на Яндекс.Диск, загруженный файл, webapp-upload) заголовок генерируется GPT по содержанию, а не берётся из имени файла; имя файла остаётся подсказкой для GPT и fallback'ом
- Заголовок транскрипции теперь берётся из оригинального названия видео (как назвал автор), а не генерируется LLM. Если yt-dlp не сумел извлечь название или title выглядит как ID/хэш (типа `dQw4w9WgXcQ`) — fallback на GPT-генерацию
- Шапка ответа форматируется: заголовок **жирным**, строка с каналом — _курсивом_, перед «Канал:» — эмодзи 📺. Формат применяется в caption у `.txt`-документа и в коротких текстовых ответах. Внутри .txt — plain-шапка с тем же эмодзи

### Added

- Таймкоды в `.txt`-файлах транскрипции: имя спикера отдельной строкой, под ним строки `[м:сс.ммм] текст` / `[ч:мм:сс.ммм] текст`; каждое предложение — своя строка с таймкодом начала (word-level точность AssemblyAI). Короткие ответы в чате остаются без таймкодов
- В подписи к транскрипции (caption у документа и шапка короткого ответа) отображается канал/автор источника — строка `📺 Канал: …` сразу после заголовка

### Fixed

- Кнопка «🧹 Очистить текст» перестала «съедать» / переписывать шапку (заголовок + строка с каналом): шапка вырезается перед отправкой в GPT-cleanup и приклеивается обратно к очищенному body без эвристик. Аналогично для «📝 Краткий конспект» — в LLM-промпт идёт только тело транскрипции, без шапки
- Команды `/start` и `/help` — приветственное сообщение со списком поддерживаемых входов и описанием лимитов
- Команда `/limit` — показывает текущий лимит, использовано и остаток на текущий месяц. Для пользователей без лимита отвечает «Лимит на транскрибации не установлен.»
- Месячные лимиты часов транскрибации на отдельных пользователей через `bot/data/user_limits.json` (пользователи без записи имеют безлимит). Расход хранится в `data/usage.json` по календарным месяцам UTC. При превышении лимита бот предупреждает и блокирует обработку с указанием текущего лимита.

## [1.0.0] – 2026-04-28

### Added

- Транскрибация голосовых сообщений и аудиофайлов Telegram через AssemblyAI Universal-2
- Транскрибация видеофайлов и video notes (извлечение аудио через FFmpeg)
- Акустическая диаризация спикеров с именованием и отображением прогресса в реальном времени
- GPT-4o анализ: адаптивный конспект по типу контента (лекция, интервью, монолог и др.)
- Разбивка монотранскрипта на смысловые абзацы через GPT
- Очистка и нормализация текста: кастомный словарь, word boost для ASR
- Распознавание ссылок: YouTube/RuTube/VK Video и другие (yt-dlp), Instagram Reels, Facebook, Yandex Disk, Yandex Music
- Загрузка Instagram и Facebook через встроенный Cobalt (с поддержкой cookies)
- Прямое скачивание публичных файлов с Yandex Disk через Cloud API
- Извлечение выпусков подкастов Yandex Music через RSS + yt-dlp
- Mini App (FastAPI + Caddy) для загрузки файлов из браузера напрямую в бот
- Whitelist-авторизация пользователей
- Docker Compose deployment (бот + Cobalt + webapp)
